Most recently I was Staff Software Engineer at Effortless Ads, a Google Cloud–hosted Google Ads automation platform serving 1,000+ active campaigns, where I split my time roughly 60% backend Rails and 40% React. The work most relevant to this role was a property-data ingestion pipeline I designed and led from scratch to v1 in about two months. It is a structured LLM integration rather than a chat feature: link discovery combining string-approximation scoring with the OpenAI API; multi-page parsing across meta tags, JSON-LD and regex; semantically chunked HTML with chunk classification feeding field extraction; and normalization that reconciles one to six competing data sources per property. Embeddings (text-embedding-3) drive the retrieval and matching steps, and an LLM-based filter selects usable property images. It reached ~98% primary-source success, with a ~2% fallback path through Google Search to secondary listing sites when a primary source failed, and it runs thousands of jobs a day on Cloud Functions and Cloud Run. Getting there required measuring output quality continuously — per-field extraction accuracy, per-source disagreement rates, and regression checks against a labeled property set — because with non-deterministic models a prompt change that helps one listing type quietly breaks another. That evaluation discipline, more than any individual prompt, is what made the pipeline safe to run unattended at that volume.
